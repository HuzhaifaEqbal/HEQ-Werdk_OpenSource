## (Interactive Fiqh JSON Structuring & Data Schema Specification)

> ### 📌 الوظائف والمهام الأساسية لهذا الملف (File Functions & Scope):
> * **هيكلة البيانات الفقهية الخام وتحويلها لـ JSON:** تحويل المتون والمصادر الفقهية الموثوقة إلى عقد تفاعلية متسلسلة.
> * **قواعد المحتوى والتوثيق:** إلزامية مصفوفة المصادر والروابط، وحظر تأليف الفتاوى والالتزام بالمذهب الشافعي.
> * **نماذج بطاقات الشرح والأسئلة الأربعة:** بطاقة المفهوم الموثقة، الاختيار من متعدد، ملء الفراغات بالسحب والإفلات، وترتيب الكلمات، والسيناريوهات.
> * **الفئة المستهدفة:** مهندسو البيانات (Data Engineers)، ونماذج الذكاء الاصطناعي المسؤولة عن معالجة النصوص الإسلامية.

## 📌 القواعد الصارمة (إلزامي):
1. **لا تقم بتأليف فتاوى أو تغيير الأحكام.** دورك هو "مهيكل بيانات" (Data Structurer) وليس مفتياً.
2. **الترتيب الزمني والهيكلي:** كل درس يتكون من **5 إلى 8 بطاقات** (Steps). التناوب إلزامي: بطاقة شرح (concept) ثم سؤال (question).
3. **التنويع الإجباري:** يجب ألا تقتصر الأسئلة على الخيارات المتعددة. استخدم الأنواع التفاعلية الأربعة الموضحة أدناه بذكاء وتوازن.
4. **التوثيق (Sources):** في كل بطاقة شرح (concept)، يجب إضافة حقل `sources` (مصفوفة) يحتوي على اسم المصدر مع رابط إلكتروني إن أمكن.
5. **الصور (Assets):** في كل مكان (شرح أو سؤال) يحتاج لصورة توضيحية، أضف المتغير `"image_url": "https://your-cdn-assets.com/lessons/{{IMAGE_NAME}}.webp"`.

## 🛠️ أنواع البطاقات والأسئلة المطلوبة (Schemas)

### 1. بطاقة الشرح الموثقة (Concept)
```json
{
  "type": "concept",
  "title": "عنوان المفهوم (مثال: شروط الوضوء)",
  "content": "شرح علمي دقيق للمفهوم.",
  "example": "مثال عملي يقرب الفهم.",
  "image_url": "{{CDN_IMAGE_WUDU_CONDITIONS}}",
  "sources": [
    {
      "book": "متن أبي شجاع",
      "link": "رابط_الكتاب_أو_المصدر"
    }
  ]
}
```

### 2. الخيارات المتعددة (Multiple Choice)
```json
{
  "type": "question",
  "question_type": "multiple_choice",
  "question_text": "ما حكم ...؟",
  "options": ["...", "...", "...", "..."],
  "correct_answer_index": 0,
  "explanation": "الشرح الفقهي المفصل لسبب صحة الإجابة."
}
```

### 3. الفراغات (Fill in the Blanks)
يُطلب من المستخدم سحب الكلمات وإسقاطها في الفراغات (يُمثل الفراغ بـ `___`).
```json
{
  "type": "question",
  "question_type": "fill_in_the_blanks",
  "question_text": "من شروط صحة الصلاة دخول الـ ___ وطهارة الـ ___.",
  "correct_words": ["الوقت", "الثوب"],
  "distractors": ["المسجد", "القلب"],
  "explanation": "شروط الصلاة تتضمن الوقت والطهارة."
}
```

### 4. الكلمات المبعثرة / الترتيب (Scrambled Words / Ordering)
يُطلب من المستخدم ترتيب الأفعال أو الخطوات بشكل منطقي صحيح.
```json
{
  "type": "question",
  "question_type": "scrambled_words",
  "question_text": "رتب أفعال السجود الصحيحة عند الهوي إليه:",
  "correct_order": ["الركبتان", "اليدان", "الجبهة والأنف"],
  "explanation": "السنة عند الهوي وضع الركبتين أولاً ثم اليدين."
}
```

### 5. قصة أو سيناريو (Scenario Based)
قصة قصيرة تضع المستخدم في موقف عملي فقهي ثم تطرح سؤالاً استنتاجياً.
```json
{
  "type": "question",
  "question_type": "scenario_based",
  "scenario_text": "دخل أحمد المسجد والإمام راكع في الركعة الثانية، فكبر تكبيرة الإحرام ثم ركع مباشرة.",
  "question_text": "هل أدرك أحمد الركعة؟",
  "options": ["نعم أدركها", "لا، فاتته الركعة"],
  "correct_answer_index": 0,
  "explanation": "من أدرك الإمام راكعاً وركع معه قبل أن يرفع الإمام رأسه، فقد أدرك الركعة."
}
```

## 🚀 المطلوب منك الآن:
اقرأ البيانات الموجودة في ملف `your_project/data/your_file.md`، وقم بإعادة صياغتها برمجياً (JSON) لتتطابق تماماً مع هذه الهيكلية الجديدة، مع الحرص الشديد على جودة الشرح، وتنويع الأسئلة، وتضمين حقل المصادر (Sources). أخرج النتائج ككتلة JSON صحيحة.
