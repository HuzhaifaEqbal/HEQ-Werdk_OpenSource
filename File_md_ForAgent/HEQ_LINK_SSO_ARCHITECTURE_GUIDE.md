# 🌐 الدليل الهندسي الشامل لبنية تسجيل الدخول الموحد (SSO)
## (Single Sign-On SSO: Hybrid Web & App Architecture Specification)

> ### 📌 الوظائف والمهام الأساسية لهذا الملف (File Functions & Scope):
> * **هندسة المصادقة الموحدة الهجينة (Hybrid Universal SSO):** الجمع بين فتح التطبيق المباشر (App Links) وصفحة الويب الاحتياطية (Web Fallback) بدون انتظار تحديثات المتاجر.
> * **مخطط تدفق البيانات (Auth Flow Diagram):** دورة تبادل الأكواد الآمنة (OAuth2-Style Code Exchange) بين تطبيقك وخادم SSO عبر الروابط العميقة.
> * **تكامل واجهات ومسارات الويب:** توثيق مسار `GET /sso/authorize` ومعاملات `client_id` و `redirect_uri`.
> * **الفئة المستهدفة:** مهندسو الواجهة الخلفية، مهندسو تطبيقات Flutter، ومهندسو أمن المعلومات.

## 💡 1. الإجابة الحاسمة والمباشرة: هل يلزم تعديل ورفع تحديث لنسخة المتجر لتعمل الميزة؟

### المفاجأة السارة: **لا يشترط تحديث نسخة المتجر ليعمل الربط فوراً!**

* **إذا قمنا بتجهيز "صفحة ويب للمصادقة" (Web SSO):**
  ستعمل الميزة فوراً بنسبة **100% لجميع المستخدمين**، حتى لو كانت النسخة المثبتة على هواتفهم قديمة، وحتى لمن لا يملك تطبيق المصادقة أصلاً، ودون الحاجة لانتظار مراجعة وتحديثات المتجر.
* **تحديث تطبيق المصادقة على المتجر لاحقاً:**
  يعتبر **تحسيناً وتطويراً إضافياً (Native Enhancement)** لجعل العملية أكثر سرعة بنقرة واحدة داخل التطبيق، ولكن المنظومة لا تتوقف عليه نهائياً بوجود صفحة الويب.

## 🛠️ 3. ما المطلوب برمجته في سيرفر SSO (المرحلة الفورية - Web SSO)؟

سيرفر الـ SSO (`your-auth-sso.com`) لديه مسار توليد الكود في قاعدة البيانات `POST /api/sso/generate-code` ومسار التحقق `POST /api/sso/verify-code`.

**المتبقي فقط هو إضافة واجهة ويب خفيفة وسريعة (Web Route):**

### أ. إنشاء مسار واجهة الويب في السيرفر:
* **المسار:** `GET /sso/authorize`
* **المعاملات المطلوبة:**
  `?client_id=your_client_id&redirect_uri=your_scheme://auth_success`

### ب. شاشة المصادقة في المتصفح (Web Page):
صفحة HTML/CSS تفاعلية سريعة بنفس الهوية الداكنة والذهبية:
1. **في حال كان المستخدم مسجلاً دخوله في المتصفح مسبقاً:**
   * تظهر له بطاقة أنيقة:
     > *"التطبيق يطلب الوصول إلى حسابك (الاسم، البريد، الصورة الشخصية)."*
   * زر كبسولي: **[ تأكيد ومتابعة إلى التطبيق ]** وزر **[ إلغاء ]**.
2. **في حال لم يكن مسجلاً دخوله:**
   * نموذج بسيط لإدخال البريد الإلكتروني وكلمة المرور (أو رمز OTP).
   * بمجرد إدخالها، تظهر نافذة الموافقة.

### ج. كود التوجيه بعد الموافقة (Redirect Callback):
عند ضغط المستخدم على زر "تأكيد ومتابعة"، يقوم السيرفر بـ:
1. توليد كود الـ SSO بنفس الآلية وتخزينه في جدول `sso_auth_codes` لمدة دقيقتين.
2. عمل إعادة توجيه فورية من المتصفح (HTTP 302 Redirect):
   ```http
   HTTP/1.1 302 Found
   Location: your_scheme://auth_success?code=SSO_5a9b7c2d1e0f...
   ```
3. يقوم متصفح الهاتف فوراً بإغلاق نفسه وتسليم الرمز لتطبيقك، فيدخل المستخدم حسابه مباشرة.

## 📱 4. ما المطلوب في تحديث تطبيق المصادقة القادم على المتجر (المرحلة الثانية - In-App SSO)؟

عندما تقررون رفع إصدار جديد لتطبيق المصادقة على المتجر، يتم تضمين التالي:

### أ. دعم الروابط العميقة وروابط التطبيقات (Android App Links & iOS Universal Links):
في `your_project/android/app/src/main/AndroidManifest.xml`:
```xml
<!-- تفعيل المخطط المباشر your_auth_scheme:// -->
<intent-filter>
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data android:scheme="your_auth_scheme" android:host="auth" />
</intent-filter>

<!-- تفعيل مسار الويب your-auth-sso.com/sso -->
<intent-filter android:autoVerify="true">
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data android:scheme="https" android:host="your-auth-sso.com" android:pathPrefix="/sso" />
</intent-filter>
```

### ب. في كود Flutter داخل تطبيق المصادقة:
* الاستماع للرابط عند فتحه:
  ```dart
  if (uri.path.contains('/sso') || uri.scheme == 'your_auth_scheme') {
    // فتح نافذة سفلية (BottomSheet):
    // "هل توافق على تسجيل الدخول إلى التطبيق بحسابك الحالي؟"
    // عند الموافقة: استدعاء POST /api/sso/generate-code
    // ثم إطلاق: launchUrlString('your_scheme://auth_success?code=$code');
  }
  ```

## 📋 5. جدول المقارنة وخارطة الطريق (Roadmap)

| الخاصية | الخيار (1): عبر صفحة الويب (Web SSO) | الخيار (2): عبر التطبيق مباشرة (In-App SSO) | النمط الموصى به: الهجين (Hybrid) |
| :--- | :--- | :--- | :--- |
| **هل يحتاج تحديث المتجر؟** | ❌ **لا إطلاقاً** (يعمل فور نشر السيرفر) | ✅ نعم (يتطلب بناء ورفع ومراجعة) | 🌟 يعمل فوراً بالويب، ويتحسن مع التحديث |
| **تجربة المستخدم** | يفتح المتصفح ثوانٍ ثم يعود تلقائياً | انتقال فوري بين التطبيقين | الأفضل عالمياً (إذا التطبيق موجود يفتحه، وإلا يفتح الويب) |
| **الأمان** | عالي جداً (OAuth2 معتمد) | عالي جداً (تشفير داخلي) | أعلى معايير الأمان المعتمدة |
| **وقت التنفيذ** | **ساعات قليلة** (صفحة ويب ومسار في السيرفر) | يحتاج دورة بناء واختبار ورفع | تبدأ بالويب فوراً وتدرج التطبيق لاحقاً |

## 🎯 6. الخلاصة والتوصية لمدير المشروع والمهندسين

1. **الخطوة الفورية التي لا تحتاج انتظار المتجر:**
   تكليف مهندس سيرفر الـ SSO بإضافة صفحة الويب ومسار `GET /sso/authorize`. وبذلك تعمل ميزة تسجيل الدخول الموحد بنجاح 100% لجميع المستخدمين.
2. **الخطوة اللاحقة المجدولة:**
   في التحديث القادم للتطبيق على المتجر، يتم إضافة مسار الـ App Link لفتح التطبيق مباشرة لمن يملك أحدث نسخة.
