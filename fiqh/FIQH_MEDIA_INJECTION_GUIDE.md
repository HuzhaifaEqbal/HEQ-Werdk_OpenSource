# 📘 المعايير الهندسية لحقن الوسائط والبيانات الفقهية
## (Fiqh Media Assets & Data Injection Architecture Specification)

> ### 📌 الوظائف والمهام الأساسية لهذا الملف (File Functions & Scope):
> * **المرجع التشغيلي لمسارات الفقه:** مراجعة وهيكلة وحقن الوسائط في عقد الصلاة، الزكاة، الصيام، والحج.
> * **القاعدة التقنية الصارمة (Zero-Terminal Rule):** حظر أوامر الطرفية لحماية التشكيل الفقهي العربي والاعتماد على أدوات التحرير المباشرة.
> * **مخططات الـ JSON للدروس والـ Boss Level:** مواصفات مصفوفة `steps` المتناوبة والاختبارات الملكية الشاملة.
> * **الفئة المستهدفة:** مهندسو البيانات، مصممو الوسائط الإسلامية، ونماذج الذكاء الاصطناعي.

---

## 🛑 القاعدة التقنية الذهبية الصارمة (Zero-Terminal Rule)
> [!CAUTION]
> **ممنوع منعاً باتاً وتشغيلياً استخدام أي أمر تيرمينال / كونسول (مثل `run_command` أو PowerShell).**
> - سطر أوامر ويندوز يمتلك مشاكل ترميز (Encoding) حادة تتلف النصوص العربية والتشكيل الفقهي وتحولها إلى علامات استفهام `???`.
> - **التعامل مع الملفات حصرياً** عبر أدوات قراءة وتحرير الملفات المباشرة: `view_file` و `replace_file_content` و `write_to_file`.

## 📐 الهيكلية المعتمدة للملفات (JSON Schemas)

### 1. ملفات الدروس اليومية (`01_*.json` إلى `05_*.json`)
كل ملف درس هو كائن JSON يحتوي على مصفوفة `steps` بنظام **التناوب الصارم (Concept -> Question)**:

```json
{
  "steps": [
    {
      "type": "concept",
      "title": "عنوان المفهوم الفقهي",
      "content": "الشرح الفقهي المعتمد على المذهب الشافعي. [ملاحظة: تُذكر الخلافات المذهبية هنا إن وجدت].",
      "example": "مثال عملي يوضح المسألة للمتعلم.",
      "image_url": "رابط_صورة_CDN_المفرغة",
      "audio_url": "رابط_ملف_صوت_مفحوص_ومباشر_MP3",
      "sources": [
        {
          "book": "متن أبي شجاع (غاية الاختصار)",
          "link": "https://shamela.ws/book/9780/..."
        }
      ]
    },
    {
      "type": "question",
      "question_type": "multiple_choice | fill_in_the_blanks | scrambled_words | scenario_based",
      ...
    }
  ]
}
```

### 2. الاختبار الملكي الشامل (`06_boss_level_*.json`)
- مصفوفة مباشرة `[...]` بدون كائن `steps`.
- يحتوي على **5 أسئلة استنتاجية قوية وشاملة**.
- **لا يحتاج لصور إطلاقاً** (لأنه اختبار احتياطي للطوارئ يُعرض عند تعذر التوليد السحابي).

## 🎧 استراتيجية وقواعد الصوتيات الحية (Audio Strategy)

### أ. الشواهد القرآنية (Quranic Ayahs)
- **المقرئ المعتمد:** فضيلة الشيخ **سعود الشريم** (128kbps).
- **قاعدة مسار الرابط:**
  `https://everyayah.com/data/Saood_ash-Shuraym_128kbps/{SURAH_3DIGITS}{AYAH_3DIGITS}.mp3`
  *(تنبيه حاسم: اسم المجلد `Saood_ash-Shuraym_128kbps` بدون حرفي ee في آخره).*
  - مثال سورة المائدة (005) آية 6: `https://everyayah.com/data/Saood_ash-Shuraym_128kbps/005006.mp3`

## 🎨 دليل هندسة برومتات الصور (Google Flow Prompts Guide)

### 1. النمط الفني المعتمد (Visual Style)
- **الأسلوب:** `A clean minimalist Islamic vector art illustration`.
- **التظليل والخطوط:** `Smooth digital vector lines, elegant flat cel-shading with warm earthy tones, no room elements`.
- **ممنوع منعاً باتاً:** استخدام كلمات `3D`, `Claymation`, `Pixar`, `Hyper-realistic` لضمان الحفاظ التام على وحدة الهوية الفنية.

### 2. هوية الشخصية والامتثال الشرعي (Faceless & Branding)
- **الشخصية:** رجل مسلم بثوب بيج/ترابي وكوفية صلاة بيضاء ولحية مهندمة.
- **الامتثال الإسلامي لطمس الملامح (Faceless):**
  `The character's face has absolutely no facial features (no eyes, no nose, no mouth)`.
- **شريط الحقوق والعلامة التجارية:**
  `across the eye level is a modern horizontal textured paint brush stroke banner neatly inscribed with the clean white text "HEQ Werdk"`.
  *(هذا الشريط يضمن بقاء اسم التطبيق عند تفريغ الخلفية ويحقق الطمس الشرعي التام).*

### 3. خلفية التفريغ الموحدة (Cutout Ready Background)
- يجب أن تكون الخلفية مسطحة بلون رمادي موحد محايد:
  `Completely isolated subject on a solid uniform flat grey background (#E2E8F0) for background removal cutout, zero background room elements, no windows, no walls`.

### 4. الدقة الفقهية والتشريحية (Fiqh Anatomical Precision)
يجب أن يصف البرومبت أدق التفاصيل الفقهية للركن أو الهيئة:
- **في الوضوء:** غسل اليدين شاملاً المرفقين مع تشمير الثوب، مسح الرأس بحدود شعر الرأس.
- **في الخفين:** مسح **أعلى الخف** (ظاهره) بأصابع مفرجة، وليس مسح أسفل النعل.
- **في التيمم:** وضع الكفين على الصعيد، مسح اليدين حتى **تطويق كامل مفصل المرفقين**.
- **في الصلاة:** استواء الظهر في الركوع، السجود على الأعضاء السبعة، الإشارة بالمسبحة في التشهد.

## 🔄 مسار العمل التشغيلي خطوة بخطوة (Operational Workflow)

1. **الخطوة 1: فحص الملف الفقهي:**
   - قراءة الملف المستهدف، واستخراج الخطوات المفتاحية المحتاجة لصور وصوتيات.
2. **الخطوة 2: عرض الصوتيات والبرومتات للمستخدم:**
   - تجهيز روابط الصوتيات المطابقة 100%.
   - تجهيز برومتات Flow بالإنجليزية مطابقة للقواعد أعلاه.
3. **الخطوة 3: حقن الصوتيات:**
   - فور موافقة المستخدم، يتم حقن روابط الصوتيات فوراً بالملف عبر `replace_file_content`.
4. **الخطوة 4: استلام روابط الصور وحقنها:**
   - يولد المستخدم الصور على Flow، يفرغ الخلفية، يرفعها على Bunny CDN (`werdk-cdn.b-cdn.net/tahara/...`).
   - فحص الروابط عبر `read_url_content` للتأكد من وصولها.
   - حقن روابط الصور في `image_url` بدلاً من الوسوم المؤقتة `{{CDN_IMAGE_...}}`.
5. **الخطوة 5: الفحص النهائي والمصادقة:**
   - استعراض الملف كاملاً والتأكد من سلامة كود JSON، عدم وجود أي وسم غير مستبدل، وتطابق الأرقام والمصادر.
